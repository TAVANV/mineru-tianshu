# 第二批：可选功能与任务生命周期适配

## 已实现

| 功能 | 默认行为与入口 |
| --- | --- |
| 审计日志 | 记录变更请求（登录成功/失败、主动登出、注册、用户/API Key 操作、配置变更及任务操作）。后台有界队列批量写入，不把密码、Key 或请求体写进日志。管理员可分页查询、按操作筛选，默认保留 90 天。 |

管理入口：**系统配置 → 可选功能**。原系统配置表单及任务提交页 RustFS 开关保留。任务提交页新增可选回调地址。

图片描述配置在实际处理阶段读取，已在处理但尚未开始描述的任务也可能使用新配置。默认 Webhook 配置则在任务提交时快照，仅影响随后提交的任务。本次没有引入上游整套认证重构或按 API Key 绑定回调的管理界面。

## Webhook 投递协议

任务提交时把回调配置保存到独立表，密钥不放在公开任务 options 中。SQLite 终态更新触发器在同一事务内写入投递记录，覆盖正常完成、子任务失败联动、重试封顶和崩溃恢复中的终态更新。父任务成功仅在合并完成后产生通知。

调度器后台处理投递；失败指数退避，默认最多 5 次，耗尽后标为 dead。调度器中途崩溃后通过租约到期恢复。投递采用**至少一次**语义，接收方必须按 event_id 去重；不能保证只收到一次，也不能依赖不同终态通知的到达顺序。

示例请求体：

```json
{
  "task_id": "...",
  "file_name": "example.pdf",
  "status": "completed",
  "retry_count": 0,
  "completed_at": "2026-09-15 04:00:00",
  "event_id": "..."
}
```

- `X-Tianshu-Event-Id`：稳定的事件 ID，重试不变。
- `X-Tianshu-Signature`：配置密钥时为 `sha256=` 加 `HMAC-SHA256(secret, 原始请求体字节)` 的十六进制值。
- `Authorization`：配置时原样发送，只对管理员默认目标有效。
- 自定义任务回调地址与默认地址不同时，不继承默认签名密钥或 Authorization，避免把默认凭据发送到其他目标。
- 内网、回环目标需管理员显式填写精确 `hostname:port`，例如 `callback.internal:8080`；链路本地/组播/未指定地址始终拒绝。
- 每次投递重新验证解析地址，连接固定到已验证 IP，TLS 仍校验原域名；不自动跟随重定向，不使用环境代理。
- 回调失败不改动解析结果。配置更新不会改写已经提交任务的回调快照；内网白名单则在每次投递时重新读取。

## 取消、重试与恢复

取消是任务状态与队列层的取消。**不会强杀正在执行的模型调用或 LibreOffice 子进程**；它们返回后不能把已取消任务改成成功/失败，当前计算占用会在调用结束后释放。取消不会删除正在使用的文件。

取消与子任务创建用 SQLite 写事务串行；子任务完成计数按真实状态重算，合并认领标记确保只有一个 Worker 开始合并。重试仅允许失败的根任务，且要等原子任务全部终结；重试会在写锁内先清理旧输出，再置回 pending 并入队，重新初始化父任务状态。已取消任务不能重试或恢复。

新增 merge_claimed 列及 Webhook 表/触发器均在启动时迁移；保留原数据字段与第一批 WAL/FULL、心跳、PID 探活、重试上限和父任务回收逻辑。升级前仍使用第一批的在线备份脚本。

## 格式范围与边界

- ZIP 最多 1000 个条目，解压总量最多 512 MiB，单条目压缩比上限 200；拒绝目录穿越、绝对路径、Windows 路径、符号链接、重复路径和加密条目。
- ZIP 只处理受支持文件，忽略不支持的文件与隐藏目录；不递归解析嵌套 ZIP。混合格式走现有自动路由；PDF/图片沿用用户选择的引擎，Office 保留现有定制解析路径。
- 任一子任务失败会使父任务失败，不把部分结果冒充完整成功。重试根任务会重新处理整个包。
- EPUB 不处理 DRM/加密内容；按 spine 顺序转换 XHTML 为 Markdown，提取本地图片，移除远端图片及脚本，不还原书籍的复杂 CSS 排版。
- 图片描述每次解析最多 30 张（可配置，PDF 分片分别计数），单图最大 20 MiB；失败跳过并保留原解析结果。无需配置公共模型地址，可使用内网兼容接口；默认不发送图片到任何模型服务。
- 审计为有界、尽力记录：最多排队 2048 条，每批最多 100 条；锁等待最多 100ms。队列满、写入失败或进程退出时可能丢日志，不阻塞业务。

## 发布前审查修复

针对五项审查问题补充了 `tests/test_review_regressions.py`：

1. 旧 Worker 的失败若未通过 worker_id/状态校验，不再触发父任务失败联动；数据库回调同样要求子任务已确认失败。
2. JSON 图片路径字段按完整路径替换；Markdown/HTML 正文仅替换图片引用，保留前后段落和多图内容。
3. ZIP 完整 PDF 与 PDF 分片通过 archive_index/chunk_info 区分。完整成员继续按页数/体积拆分，形成 ZIP → PDF → 分片；PDF 合并后才推进 ZIP。失败、取消、重试、恢复和清理覆盖所有层级，最终通知仍仅发送 ZIP 根任务。按体积拆分使用真实页密度并允许单页分片，避免少页大文件退化为整份解析；拆分失败不回退整份解析。
4. 图片交接、RustFS URL 改写及本地预览共用支持转义方括号的图片引用解析，覆盖一张含方括号描述、另一张普通描述的实际 HTTP 交接响应。
5. 邀请码配置保存端与管理页面均限制 100 字符；回归覆盖 101 字符被拒绝，以及 100 字符保存后注册成功。

新增 15 项回归用例，包含真实 PDF 文件的页数/大小拆分与两级合并；模型解析部分仍使用隔离替身，没有宣称完成真实 GPU 验收。

### 第二轮补查修复

- 父任务恢复在 `BEGIN IMMEDIATE` 写事务中读取、判断、更新和删除后代，更新同时要求状态仍为 processing；操作失败时状态与后代记录一起回滚。
